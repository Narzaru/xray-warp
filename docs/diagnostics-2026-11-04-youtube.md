# Диагностика буферизации YouTube, 4 ноября 2026

При воспроизведении видео наблюдалась задержка заполнения буфера около 22 секунд. В DevTools одновременно появлялись ответы HTTP 403 и ошибки DNS. В разобранной записи эти ошибки относились к служебным запросам плеера. У запроса, по которому поступало видео, тоже наблюдалась задержка DNS. Установить единую причину по этой записи не удалось.

## Проверки

- На нескольких узлах Google Global Cache установка TLS через прямой выход зависала. Другие узлы отвечали в той же серии измерений. Сравнение по фиксированному адресу с сохранением SNI помогло отделить задержки DNS от задержек TLS.
- Прямой выход и WARP сравнивали через один и тот же VLESS/XHTTP-вход. В использовавшемся тогда варианте MicroWARP сервер MicroSOCKS поддерживал TCP. Для результатов по QUIC и UDP важно учитывать версию SOCKS-сервера. Позднее рабочий профиль перешёл на Hev с UDP ASSOCIATE.
- Для sslh включили числовые адреса в логах, чтобы обратный DNS не задерживал цикл обработки соединений. После переключения проверили SSH, TLS и полный XHTTP-путь. Влияние этого изменения на буферизацию осталось неопределённым.

## Как сравнить повторный эпизод

Зафиксируйте домен назначения, протокол медиазапроса (h2 или h3), этап задержки и выбранный маршрут Xray. Сопоставляйте один запрос в сопоставимых условиях. HAR, идентификаторы клиентов, полный URL с параметрами и сырые логи храните у оператора.

Рабочие правила для российских назначений и порядок проверки точечного исключения описаны в [руководстве по исходящему трафику](outbound.md). Семейства адресов и таймауты рассмотрены в [сетевой документации](network.md).
