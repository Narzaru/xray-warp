## Сопоставление Xray с репозиторием

[Маршруты](../config/xray/routing-warp-ru.json) и [outbounds](../config/xray/outbound-warp.json) при сравнении как JSON совпали и с постоянным шаблоном панели, и со сгенерированным `/app/bin/config.json`. Уровень 0 рабочего конфига совпал с [policy.json](../config/xray/policy.json), включая `connIdle: 1800`. В шаблоне SQLite тот же таймаут; поля `statsUserOnline` там нет, в итоговом конфиге оно равно `true`.

Порядок при `IPOnDemand`: API → запрет `geosite:category-ru` для `in-10000-tcp` → запрет `geoip:ru` для того же входа → запрет `geoip:private` → запрет BitTorrent → остальные TCP/UDP в `warp-out`. На клиентском входе включён sniffing HTTP/TLS/QUIC с `routeOnly: true`. Наличие правила не гарантирует, что у каждого UDP-потока удастся распознать имя.

## Что ещё не применено

Есть включённый systemd-таймер, исходный bootstrap-план и заявка на [точечное исключение](../config/xray/youtube-cache-exception.json). Хеши текущего Compose, нормализованного runtime и шаблона БД соответствовали относящимся к ним значениям в планах. На момент сверки у 3x-ui **нет** отдельного mount для геоданных, каталога `/opt/x-ui/geodata` ещё нет, в действующих правилах исключения нет. Ближайшее запланированное окно — **15 ноября 2026, 04:00 НСК**. Подтверждение после окна — [по журналу и отчёту применения](operations.md#отдельное-обновление-geoip-и-geosite).

Замена базового Compose версией из репозитория до этого окна изменила бы утверждённый SHA и остановила bootstrap. Репозиторий содержит также установщик для новых хостов и исторические миграции: он не предназначен для слепого копирования поверх рабочего каталога.

SHA-256 базового Compose совпал с указанным в обновлённом плане. Хеши действующего конфига Xray, шаблона панели и заявки сохранились. Таймер указывает на 15 ноября, 04:00 НСК. Восстановление прежнего базового Compose потребовало бы согласования и с планом geodata, и с фактическим состоянием после ночного окна.
